# Cockpit V0 tickets

Status: **final (Phase 2).** Written against SPEC v2 (FROZEN 2026-11-04). Changes to scope or ownership need a DECISIONS.md entry.

Flow (DECISIONS D-003): each ticket gets a real GitHub issue and a PR via `gh ... --repo TeddySabatier/jobsync-cockpit`, after `gh auth switch --hostname github.com --user TeddySabatier` (check `gh api user --jq .login` first). Branches are **stacked**: ticket N branches from ticket N-1's branch (`cockpit/<n>-<slug>`), because later tickets need earlier code, and its PR targets that branch (C-01's targets `main`). The reviewer verdict goes in as a PR comment. No merges by the agent.

Tickets run strictly one after another (C-01 → C-11) in one worktree, so none run in parallel. Even so, every file has exactly one owner (new files and core files alike). A later ticket may only touch an earlier ticket's file if the table lists it under "also edits", and only a ticket that depends on it.

Test command used by every ticket:
- `npm run lint`
- `npx tsc --noEmit`
- `npx vitest run <ticket test files>`

Test conventions (SPEC §10): Vitest's default environment is jsdom (`// @vitest-environment node` for fs, DB and static tests); `server-only` is already aliased, so tests need no stub; mock `@/lib/db` and `@/utils/user.utils`; integration tests use C-02's SQLite harness. `jsdom` is already the Vitest environment: C-01 checks that it is a devDependency and adds it only if missing.

The full suite runs after C-02 (schema), C-04 (token scopes, rate limit), C-06, C-09 and C-11.

Tiers:
- `@fast` = composer-2.5-fast (T0/T1);
- `@medium` = claude-sonnet (T1+);
- T2 = orchestrator (Opus). It designs and reviews security tickets and does all alignment checks.

The reviewer is always a different model from the coder.
