# Cockpit V0 — UX review (SPEC §2.1, §5, §6.1; V0 scope §8)

1. **Important** · §5.3 (Send confirm) · **Problem:** The send confirmation repeats From, To, Subject, and attachment name only—not the email body or cover letter. On mobile (stacked panels), the user may tap Send after skimming fit/CV without re-reading the actual message text in one place. · **Fix:** Extend the confirm dialog (or a mandatory “Review before send” step) with scrollable plain-text body and a cover-letter excerpt/link; require explicit acknowledgment if body was edited since load.

2. **Important** · §6.4 step 5 · **Problem:** If Gmail send succeeds but the post-send DB transaction fails, `sendStartedAt` stays set and the package cannot be sent again; the spec only mentions logging—no UI state, message, or recovery path. Daily review dead-ends on a job that may already have mail in the outbox. · **Fix:** Define a visible “Send incomplete—contact support / note Gmail message id” state, admin or self-serve clear of `sendStartedAt` after verified duplicate, and show `SentEmail` partial data if any.

3. **Important** · §5.4 + §2.1 · **Problem:** After any CV string edit, Send is blocked until the bot re-renders PDF via “Ask the bot to re-render” (a change request). The user cannot complete the day’s send for that job without an async bot round-trip—no V0 in-app PDF regen (§8). · **Fix:** In UI, treat stale PDF as a first-class queue blocker (badge on list + detail), auto-switch to `changes` or pin instruction; optionally warn before Edit that send will be deferred ≥24h.

4. **Important** · §5.3 (Mark applied manually) · **Problem:** “Mark applied manually” is a terminal `sent` action with only a generic confirm dialog; it sits in the same sticky action bar as Send/Reject. Mis-tap marks the job applied in JobSync with no email audit row (`§6.1`). · **Fix:** Distinct visual treatment (secondary/destructive), confirm copy that names company/role and posting URL, type-to-confirm or second step; hide behind overflow menu on mobile.

5. **Important** · §5.2 + §5.3 · **Problem:** Queue rows show status and recipient but not send-readiness (Gmail connected, `cvPdfStale`, missing CV file, empty `emailTo`). User can approve many packages on desktop/phone, then discover blockers only on detail/Send. · **Fix:** Add compact readiness chips on each row (e.g. “Gmail”, “PDF stale”, “No CV”, “Link apply”) and filter/sort “ready to send” within `todo`.

6. **Minor** · §5.3 (Keyboard) · **Problem:** `j`/`k` only advance within the `todo` queue on the detail page—not from the queue list, not on `changes`/`sent`/`rejected` tabs. Power users doing daily review must click back to list repeatedly. · **Fix:** Document limits in UI hint; optionally enable next/prev from queue rows and respect active tab’s ordering (still V0-simple).

7. **Minor** · §5.3 (Version selector) · **Problem:** Non-active versions show a read-only banner, but the header still shows company/role/fit like the active package; easy to review the wrong PDF/email and wonder why Send is missing. · **Fix:** Strong banner (“Viewing v2—superseded; open v3 to act”), disable or hide action bar entirely on non-active versions, default deep links to active version only.

8. **Minor** · §5.3 (Email preview) · **Problem:** Attachment is shown as file name only; no size or “matches cvJson” cue beyond separate `cvPdfStale` warning elsewhere. User must infer correctness before Send. · **Fix:** Show file size, last bot submit time, and inline stale warning in the email preview panel next to Attachment.

9. **Minor** · §5.2 (Empty/error) · **Problem:** Empty states are one sentence per tab; no guidance when Gmail is not connected while `todo` has approved email packages, or when OAuth callback fails (`?error=` only on settings, not queue). · **Fix:** Persistent callout on `/dashboard/review` when Gmail disconnected and ≥1 approved package needs send; link to settings with error text surfaced once post-login.

10. **Minor** · §5.3 (Phone action bar) · **Problem:** Up to seven conditional actions in a sticky bottom bar (Approve, Unapprove, Reject, Request changes, Edit, Send, Mark manual)—primary Send competes with Reject/Edit for thumb zone on 375px cards layout. · **Fix:** Single primary CTA per state (e.g. Send OR Approve), demote destructive/secondary to menu sheet; keep Send as full-width when `approved` and ready.
